# 消息规则

消息规则对已进入平台的消息按配置节点顺序处理。规则不是任意流程画布，也不因保存草稿自动投入运行。

## 创建与配置

在“规则与自动化 → 消息规则”点击“创建规则”，填写名称、说明和适用方向或范围。节点目录来自当前部署；选择节点后填写参数，复杂值使用 JSON，按上移和下移确定顺序。

每个节点输入必须符合页面返回的配置 Schema。JSON 格式合法只是第一步，未知字段和未知节点可能使历史配置只能只读查看。不要删掉原字段来让旧配置勉强保存。

## 保存与发布

保存建立草稿，发布生成不可变执行版本。检查发布状态后再发送测试消息；旧执行记录仍引用当时版本，不以后续编辑覆盖。是否可停用、启用或删除以当前状态和权限为准。

## 执行记录

进入“执行记录 → 上行规则执行”，按规则、状态和时间查询。核对触发消息、冻结版本、尝试及节点结果。动作受理不代表外部副作用完成，设备或通知结果需查看其所属记录。

如果保存或发布响应丢失，先读取原操作和当前版本，不重复发布猜测状态。签名、权限、额度或节点不支持的错误应按具体原因处理。

## 如何选功能

消息转换或顺序处理选消息规则；属性条件触发业务动作选[自动化](/docs/business/automation)；用户手动触发一组动作选场景；固定数值异常管理选[告警规则](/docs/business/alarms)。避免让多个功能对同一测试输入重复控制设备。
