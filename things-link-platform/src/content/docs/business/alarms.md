# 告警规则与通知

告警规则把设备属性变化转换为可维护的告警实例和事件。通知路由进一步决定向谁发送信息；告警产生与通知送达要分开核对。

## 配置规则

进入“运行与告警 → 告警规则”，点击“创建规则”。填写名称、告警类型、目标设备和数值属性标识，设置比较方式、阈值、持续秒数以及恢复比较和阈值。当前规则只支持固定数值比较，不能在阈值栏输入任意表达式。

恢复回差可减少临界值附近反复触发，例如教学中温度高于30触发、低于28恢复。阈值仅用于测试，生产值需依据业务要求确认。修改规则不会改写已有实例与事件。

## 通知组和模板

在“通知组”建立收件组，按部署支持的渠道配置收件人。目标以脱敏形式显示。创建通知模板时使用页面列出的可用变量，变量名和大小写必须完全一致；中文注释帮助理解，不是变量本身。

回到规则的通知路由，将通知组、模板和事件阶段关联。配置存在并不证明渠道可达；真实邮箱或 Webhook 接收端应另外核对。

## 查看历史

进入“告警历史”，按设备、状态和时间查实例，在抽屉看摘要、事件及投递记录。人工确认与清除是维护动作，不改写原始事件。外部操作后显式刷新读取最新事实。

通知记录是服务端投递意图和执行状态。发送成功不等于收件人已读，远端 HTTP 确认也不等于对方业务已完成。失败或终态按页面提供的合法处理入口操作。

## 检查结果

同一测试属性依次产生触发、恢复及对应事件，通知配置和投递记录能关联。缺少通知时先查路由与渠道，不反复制造异常输入。完整教学步骤见[温湿度监测](/docs/tutorials/environment-monitoring)。
