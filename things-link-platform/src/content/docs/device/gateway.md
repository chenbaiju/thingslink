# 网关拓扑与 Modbus 点位

网关把没有独立平台连接的子设备数据汇集上报。平台保存网关和子设备的身份、拓扑与点位配置；设备侧仍需实现采集、映射和回执。

## 配置网关和子设备

1. 创建具有网关角色的设备，准备其 MQTT 凭据与接入配置。
2. 准备子设备档案与对应模型，核对所属项目。
3. 在“设备开发 → 拓扑管理”绑定子设备。
4. 网关使用自己的认证身份和 Topic，按批量代报合同携带子设备标识。
5. 核对拓扑、逐项受理结果及每个子设备的当前值和历史。

子设备不使用独立 MQTT 凭据。平台按真实拓扑确权，不能靠载荷自报项目或网关身份取得访问。某一子项被拒绝时，不能将整个批次当作全部成功。

## 配置 Modbus 点位

在“Modbus 点位”添加映射前，先取得设备寄存器文档：从站地址、功能码、寄存器地址及数量、数值类型、字节序、缩放和目标属性。把目标属性定义到对应物模型，再按页面保存或发布配置。

寄存器表中的地址有时以1起始，有时以协议偏移表示；必须按设备手册和客户端约定确认，不能直接复制显示地址。使用已知测试值逐点校验，尤其检查负数、浮点字节序与缩放。

## 配置回执和数据

发布点位后核对网关应用的是哪一配置版本及其回执。配置已保存不等于网关已应用，读到字节也不等于映射出的工程值正确。先确认配置，再对照实测值与平台属性。

## 能力范围

软件契约不代表任意 PLC、DTU 或网关型号已认证兼容。平台不因此提供通用云端 PLC 协议栈。具体型号、接线、串口或网络采集需单独验证，首次检查建议只读采集。

数据排查参见[遥测与历史](/docs/device/telemetry)，关系管理参见[设备管理](/docs/device/management)。
