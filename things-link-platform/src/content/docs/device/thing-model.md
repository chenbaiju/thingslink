# 设备类型与物模型

物模型描述设备有哪些可交换的数据和动作。先定义，再发布，再绑定设备，可以让平台按同一版本验证上报、命令和应用引用。

## 定义三类能力

| 能力 | 适用例子 | 需要填写 |
| --- | --- | --- |
| 属性 | 温度、工作模式、开关状态 | 标识、数据类型、读写或更新方式、约束 |
| 事件 | 过热、检测结果 | 事件标识、参数与必填规则 |
| 命令 | 自检、重启、调整配置 | 命令标识、输入和输出定义 |

进入“设备开发 → 设备类型”，创建类型并打开物模型工作区。在草稿中添加定义，保存后检查标识拼写和约束。单位应来自设备规范，不能从属性名推断。

## 发布与绑定

发布形成具体 `major.minor.patch` 版本及完整快照，已发布定义不能当普通草稿直接修改。创建设备选择已发布类型后，在设备详情核对实际绑定版本。兼容性由变化内容决定：删除、改型或改变既有约束不能当作无影响修订。

设备上报应明确使用其绑定的 `modelVersion`。模型版本号与版本资源 ID 不同，应用绑定还需要引用正确的版本身份。历史旧版本数据不能简单归入当前定义。

## 复合属性与未知配置

对象和数组属性使用受限 Schema，并不接受任意 JSON Schema 特性。事件参数使用独立限制，不能照搬对象属性规则。命令输入与输出也需符合其定义；保存 JSON 语法正确不等于业务校验通过。

遇到未知组件或旧配置，先查看原始定义和只读提示，显式建立支持的版本；不要通过删字段强行让旧对象变为可编辑。

## 核对结果

发布后记录类型、模型版本和属性标识，在设备详情检查绑定，在[MQTT 教程](/docs/device/mqtt)中用同一版本上报。值被拒绝时先检查类型、范围、必填字段和版本，再检查传输。
