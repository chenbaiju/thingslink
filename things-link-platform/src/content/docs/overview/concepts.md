# 核心概念

先分清对象的职责，再创建资源，可以避免把项目标识当成认证密钥，或把终端用户误当作项目成员。

## 资源关系

| 对象 | 职责 | 关键区别 |
| --- | --- | --- |
| 租户 | 持有订阅及共享资源池 | 多个项目可能消耗同一池 |
| 项目 | 组织设备、成员、规则、告警和应用 | 当前角色取决于所选项目 |
| 设备类型 | 定义一类设备的属性、事件、命令 | 不等于设备实例 |
| 物模型版本 | 已发布定义的不可变快照 | 设备绑定具体版本，不能只看类型名称 |
| 设备 | 一台设备或一个子设备的档案 | 包含自身标识、状态、当前模型及凭据 |
| 设备组 | 静态成员或按标签动态匹配 | 动态成员随事实变化，执行记录另行冻结目标 |
| 看板和应用 | 数据展示及发布入口 | 保存草稿与发布是两个动作 |

## ID 与 Key

`projectId`、`deviceId`、`thingModelVersionId` 是资源 ID，用于管理 API 与版本引用。`projectKey`、`deviceKey` 用于设备协议身份和 MQTT Topic。`productKey` 是产品识别码，`productSecret` 是注册秘密。API Key、设备密钥、登录令牌和短期订阅票据各有独立用途，不能互换。

## 两类用户

控制台成员用于管理和运维项目。终端用户用于访问应用、已授权设备或看板；终端角色和资源授权另行管理。首页“项目成员”与“我的资源”中的“用户”因此采用不同目录计数。

## 两类属性状态

**Reported** 是设备已上报的状态；**Desired** 是平台希望设备达到的状态。修改期望值不证明设备已应用设置，必须检查回复与后续上报。

同样，在线表示连接事实，活跃表示统计窗口内有活动，告警表示规则产生的事实。三者都不能单独证明设备健康。
