# 平台架构与内部部署

平台管理面处理账号、项目和配置，设备接入面处理连接、认证及消息交接，异步处理器保存数据并执行已配置的业务。部署时保留这些边界，避免长连接与业务管理互相拖累。

## 工程与运行单元

后端 Maven 聚合工程位于 `things-link/`；管理装配为 bootstrap，独立接入装配为 access。Console、WebApp、Platform 和 Agent 分别维护制品。兼容开发的全量进程不能代替正式双进程隔离验证。

```text
Console / WebApp / 业务集成 → 管理面 → PostgreSQL
设备 → EMQX或HTTP/TCP/CoAP入口 → 持久消息交接
                                     ↓
                         数据、规则、告警、任务处理
                         ↓                   ↓
                 PostgreSQL / TimescaleDB   对象存储
```

## 部署前准备

1. 明确公司服务器资源、来源白名单、实际出口和网络拓扑。
2. 准备域内可信的 TLS/DTLS 证书、信任链和安全保存的凭据。
3. 准备数据库、Redis、Kafka、Broker 和对象存储，确认容量及备份责任。
4. 按指定候选执行 Flyway 迁移及制品构建，不自动建表或手工改历史迁移。
5. 明确管理与设备端点路由、健康探针、日志、恢复及升级回退流程。

服务器启动或健康接口正常，不证明认证、租户隔离、数据链路和额度守卫通过，必须使用同一候选逐项验证。

## 静态网站和应用

Platform 构建为静态 HTML，部署需按文件与目录索引找路由，缺失返回真实404，不套用 Console 的 SPA 回退。Console 与 WebApp 是各自独立应用；地址或宿主制品变化须按各自合同重新构建。

## 备份与升级

备份业务数据库、对象与受保护配置，实际演练恢复后检查版本及关联事实。保留上一候选，按兼容与迁移规则安排回退；代码回退不自动回退数据库结构。

当前不执行公开站点、商用云、域名或 SIM 验收。部署方应使用仓库内正式操作手册，本文用于理解准备顺序，不提供未经确认的生产启动命令。
